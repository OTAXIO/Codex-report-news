# 用户确认的成品要求

## 选题、来源与时段

- 来源新增 Agent Reach 的 X 负责人推文（覆盖之前不搜 X 的限制），同时保留免费官方 RSS/Atom、官方网页和社会新闻 RSS。每小时读负责人白名单，不做全站持续搜索、不接付费 X API。官网无新公告时，负责人新鲜推文可单独入选。
- AI 官方 RSS 每期前采集；负责人推文与社会新闻每小时采集、本地去重，采集脚本不调用模型 API，最后制作时才由模型选题。月度预算目标 100–300 元（不含已有 Plus）；本次使用当前 Codex 会话和本地语音/编码，未配置额外付费模型、X 或语音 API；Agent Reach 读取是否可用以实测为准。
- AI 优先 OpenAI/GPT、Anthropic/Claude、DeepSeek、千问、智谱/GLM 等热门主体，扩展关注 MiniMax 等。AI 合格内容不设条数上限；不因可抓取就拿普通冷门论文凑数。
- 来源次序：tibo (@thsottiaux) → OpenAI 其他已核实负责人 → OpenAI 官方；其他公司为已核实负责人 → 该公司官方。保持原有热门公司次序。负责人推文需标作者和原始链接，个人观点/预告不能写成正式发布。同事件跨推文/官网合并去重，敏感内容仍先跳过。
- 社会新闻国内 3 条＋国际 3 条，排除与 AI 重复的事件。排序依据来源内时效、影响和相关性，不宣称测得全网热搜。
- 北京时间 06:00 早间新闻、12:00 午间新闻、18:00 晚间新闻。公开栏目名不用“每日新闻”。每期制作完成先到 release，再从 release 上传。
- 内容事实为主，语音字幕概括重点；不展示血腥、色情等违规画面。遇敏感内容跳过，另选；经用户审核的对应内容可进入主视频 P2，不占固定三次频次。不能把审核理解为允许违法或缺失权利的素材。

## 画面

- 白色为主背景、黑字，蓝色 #01A1FE 点缀、黑色少量辅助，不用深蓝或克莱因蓝大底，不用黄色。大色块、利落边缘参考 Persona 的视觉感觉，不复制游戏资产。
- 花纹尽量在边缘，中央干净整洁。16:9，1920×1080，30fps。AI 公司 logo 要够大，充分利用右侧空白；来自官方组织或可靠素材，不重绘假 logo。
- 每条新闻展示多个要点及必要解释；可在确有帮助、来源及使用依据清楚时使用相关高清图片，不能拿生成图冒充现场。
- 当前模板：标题 70px、要点 34–36px、解释 28–29px、字幕 40px；AI logo 区宽 460px、图片 440×440。实际预览判断，不能只根据代码认为无溢出。
- 底部同时突出 AI 动态、国内外重点新闻两个大模块并高亮当前模块；下面按每条新闻独立分段，标简短标题、高亮当前新闻，另有连续全片进度及时间。

## 口播与字幕

- 使用用户已有 Voice_Generate/GPT-SoVITS 语音，不擅改模型和训练项目。参考台词为“帝江号，我已就位，该出发了。”。
- 咬字清晰、发音正确、自然收尾，减少拖尾但不能吞尾字。现有确认配置 speed=1.0、pause=0.20、cleanup=strong、tail_style=natural、soft_release=false；撤回额外句末压缩/淡出。不机械追求更快。
- OpenAI 配音输入写 Open AI；AI 两个英文字母连续读，不插标点或句间停顿。显示稿和发音稿分别保存，画面与字幕保留 OpenAI 正式拼写。
- 国外公司/产品用正式英文名，不翻成中文。国内有正式中文名则使用中文，本期千问/千问编程助手；DeepSeek 保留英文。其他主体先核对正式名称，不乱译。
- 导览只说“这是本视频的导览。”，说完静音 2 秒展示目录，再开始正文；不读目录，不出现制作思考、审核要求或内部说明。“本期说明”章节取消。
- AI 栏目后承接：“接下来是国内外重点新闻，先来看……”并自然接第一条国内消息。
- 字幕内嵌视频，不单独上传网页。每次一行，适时切换，词组、专名、数字＋单位、版本号完整，不拆词。数字可用阿拉伯数字。避免短尾词闪现；句内时间目前按语义切分和语音长度权重估计，不能声称逐词强制对齐。
- 文稿生成使用 help-me-speech 的自然朗读与叙事检查；受众、风格和时长从当前上下文复用，不反复询问。不把内部工作表或代理思考写入公开文稿。

## 封面与标题

- 简洁、白底黑字、蓝色强调，包含真实新闻图片或公司 logo。
- 从本期核验新闻中选最值得突出的具体 AI 事件，标题和封面围绕同一事实；可吸引人，但不能泛泛写“又升级了”或胡乱概括、夸大。
- 保留发布时态和统计口径。近期消息不能假称今天刚发布；如 OpenAI 的 12 倍仅指存储读取，不是回答速度。
- 明确日期、早间/午间/晚间名称。B 站双比例 4:3 和 16:9 都要检查，标题、logo 不被裁切。

## 投稿与交付

- 视频文件名含日期、时段和栏目，例如 2026_10_26_night_晚间新闻.mp4；不可用 sample、final、最终版等无法区分日期的文件名作为上传来源。
- 分区选科技（当前页面显示科技数码）。稿件分类/合集要求 News；已实际确认存在 News 合集，配置中固定已使用合集的 ID，不能添加同名标签冒充分类。
- 创作声明为多选：同时选择“含AI生成内容”和“内容为自制：未经作者允许，禁止转载”。原创不是只加一个标签；保留必要的 AI 标识。
- 标签逐个输入后按回车，核对成真正的标签。AI、OpenAI 为优先项，按内容可加人工智能、千问、Claude、ChatGPT、AI编程、科技资讯和本期栏目，至多 10 个，不加无关品牌凑数。
- 创作活动优先相关、热门且符合条件的项。2026-10-26 观察到科技猎手约 9.6 亿次播放，仅为当日参考，不保证收益、不固定套用；付费推广不等同免费创作激励。
- 当前 Codex 负责制作与协助发布。codex-upload 已完成真实认证/只读核查与离线完整流程，制作产出后自动尝试提交；新视频完整实投仍以真实回执为准，故障时保留 release 并报告；不重复发今天已发布的视频，不擅自启用无人值守发布。
- 成功导出写已用新闻日志；成功发布再记录回执/用户确认，最后归档清理工作残留。源码、依赖、原始素材、语音模型、数据库和已用新闻日志保留。

X 路径补充：专用 Agent Reach 读取优先；允许公开镜像 Sotwe（安装时已用来发现 tibo）作为文字与来源核查备用。镜像必须核实原作者、status 链接、正文和时间；相对时间/片段只能当线索，不冒充最新完整原帖。不默认收费，不自动轮换镜像绕过登录/验证/限流。当前专用 tibo 已读通。

## tibo reset 临时新闻（最新新增）

负责人推文每小时读取。发现 tibo 新的明确额度 reset 通知时，核验后优先制作并按授权紧急发布“临时新闻”；不占北京时间 06/12/18 点三期次数。只展示该 reset 推文的作者、时间、原链接、原文及忠实中文概括；无导览、无其他新闻，保留本地语音与单行字幕。先 release，按日期＋temporary＋时分秒＋事件 ID 命名，不覆盖主片。已读历史不追发，同次重置去重，玩笑/否定/询问不触发发布。具体命令、语义核验和上传边界见 News_Video/docs/RESET_ALERTS.md（项目 docs 内同名文件）。当前自动投稿后端未验收时，完成成品后立即通知用户手动提交，不谎报已发布。


## 来源时间与负责人 X 画面（2026-10-27 最新要求）

- 所有新闻画面的“数据来源/来源”区展示信息原始发布时间，尽可能具体到分钟；有可靠时区的时间统一为北京时间，格式 YYYY.MM.DD HH:mm 北京时间。不能把采集时间、视频制作时间或转载时间冒充原发布时间。来源只有日期则只标日期，缺分钟/时区如实说明，不补造 00:00；编辑数据用 published_precision=date 标记仅日期来源，并保留原始时间证据。
- 视频可以展示 tibo 及其他已核实负责人发布的 X 消息，包括额度 reset 消息。tibo在主片最多1页，其他每位负责人在同一期视频中合计最多占 2 页画面，跨不同话题也累计；这里是 2 页视频画面，不是最多 2 条推文。临时新闻按其独立期次计算。
- 同一人的多条相关推文可合并到 1–2 页，由当前 AI 提炼“他表达了什么、意味着什么”；区分原文事实、个人观点、预告和 AI 的解释，不添造公告、重置范围或到账承诺。英文原文与中文概括明确区分，需要时标“要点概括”。
- 2 页仍容纳不下时，精选最重要且相关的信息、压缩总结或舍弃次要消息；不增加第 3 页，不缩小字号硬塞，不限制为 2 条推文，不删除关键上下文导致误解。
- 可附原始 X 推文截图或负责人头像，保留作者/账号/发布时间等必要归属，记录图片出处。截图只裁取相关推文，排除广告、无关推荐和不适宜画面；头像不冒充公司 logo。截图不能替代清晰正文、概括和单行字幕，避免用过长原文堆满两页。
- reset 紧急规则保留：明确、新鲜的 tibo 额度重置声明先核验、去重再制作临时新闻，只展示该重置相关消息及忠实解释，不混入其他话题、不占早午晚三期、不追发旧重置。主片选题仍查已用记录，避免再播同一临时消息。
- 检查时逐页核对时间精度与时区、每人总页数、总结是否忠实、配图归属、文字溢出。需要多页时在编辑 JSON 中标 author_handle、person_page_index（1/2）、person_page_count（≤2），同人的全部页统一计数，不以拆分 scene 或话题规避上限。


tibo 发音：仅口播输入替换为 `ti bo`，按用户指定的两音节连读；不要读成 table。画面、字幕、作者名与原始来源保持 `tibo`，不可改成 ti bo。规则在 config.voice.pronunciations 中。


最新发音与听感要求（覆盖旧 ti bo 规则）：tibo 口播读 tī bo，梯一声、啵轻声（短而轻、无独立升降调），中间不停顿；TTS 输入使用“梯啵”，画面/字幕/来源仍保留 tibo。中文替换是发音引导，不是已验证的强制音素接口。语气平稳、克制，避免活泼上扬。整段统一参考音频、采样设置和逐单元种子，重新生成全部语句，不局部拼接不同听感的句子。低采样温度用于减小变化，不能等同于模型原生情绪控制；最终听感仍需试听。


时间口播规范：13点48分 / 13:48 读“十三点四十八分”，48 不逐位读“四八”。仅转换语音稿，画面/字幕保留原有阿拉伯数字；分钟小于10时读“零五”等，整点读“点整”。tibo 目标为梯一声、啵轻声、两音节连读；语气平稳克制，整段统一生成。


## 当前生效：连贯语音与停顿（2026-10-27 最新）

- 若新流程仍达不到用户听感要求，再训练独立的 0.6B 候选，使用留出验证与同文稿试听选模型，通过后切换 model_path；不直接覆盖可用 Base，不单纯堆轮数。当前尚未执行 Qwen 微调。

## 2026-10-27：负责人发言、身份与口播主语（当前规则）

负责人有新鲜、正常且有信息价值的推文时优先考虑展示，不限于正式产品公告，也可展示有趣的观点或体验；明确这是个人观点、预告还是已发生事实。无公司公告也可独立入选。敏感、不完整、缺必要上下文或重复已用的内容跳过/暂缓，改选其他新闻，不硬凑数量。

主片顺序：经语义核实的tibo额度reset放在公司AI新闻之前，普通tibo发言放在公司AI新闻之后、社会新闻之前。tibo每期最多1页新闻画面，可精选合并多帖；其他已核实负责人同样在公司板块后展示，每人最多2页画面（不是2条推文），放不下就精选总结。重要reset/新模型回顾继续按important_events规则保留，不因临时稿已播而漏掉主片重点；已发布成品不重做。

口播可以不念职位，但必须有主语、原始发布时间和具体内容，例如“tibo 于北京时间10月27日13点48分发表推文，提到……”。这只是格式示例，不是一条真实新闻。分钟取原帖published转换北京时间，不用采集时间替代；跨日及回顾说清日期。缺精确时间不编造几点几分，保留可核实日期和主语；缺必要时间证据的时效快讯暂缓。显示和字幕可用数字，配音经现有pronunciation转换为“十三点四十八分”；tibo读音规则保留。避免无主语的“表示了……”“提到……”，也不机械重复一长串身份。

## 2026-10-27：固定低音量循环背景音乐

后续制作所有主片和临时新闻使用用户提供的《おしんこ》FLAC作为背景音乐。原文件已复制至本地assets/music/oshinko.flac（94.366667秒），config.background_music记录SHA256与混音参数；不依赖Downloads原文件继续存在。原始音乐及本地来源记录不进入Git或DSH交接ZIP，换机按docs/BACKGROUND_MUSIC.md准备同一文件并验哈希。

用户最终要求：全片使用固定低增益，不随播报或停顿升降，不开启ducking/sidechain；仅整片起止约0.35秒淡入淡出。循环播放到视频结束，严格裁到timings.duration，不因一首结束而提前停音/停片。配音优先，保持音色、语速、句间与概览停顿；不重训、不压尾字。

实现audio_mix.py：配音基准-16 LUFS，音乐初始目标-36 LUFS（不是音量百分比），分析200ms有效播报窗口，必要时把整条音乐统一再降低，使这些窗口音乐RMS至少比配音低20dB，并限制音乐峰值不高于-30dBFS。检测阈值、实测差值与恒定增益写入audio-mix.json；静音间隔不自动抬高音乐。不以数值检测冒充主观听感已获用户确认。

build_film和render_sample共用同一soundtrack.wav；后者不再对混音整体二次loudnorm，避免重新抬高背景。纯配音narration.wav独立保留，release保留soundtrack.wav/audio-mix.json便于复核。doctor检查音乐文件/哈希；启用时素材缺失、哈希不符、无有效配音或混音不达标均报错，不默默换曲或生成只有音乐的新闻。缓存绑定原配音/原曲哈希、时长与参数。resume-export仅续传已有成品，不借本次功能修改已发布或已导出的旧视频。


循环起点补充：首次完整播放原曲；从第二遍开始每次从原音频00:03起播放到曲尾，前3秒只播一次。audio_mix.loop_music按48kHz采样帧拼接，循环体为[3秒,原曲结束)，最后按视频时长裁切，不每轮重新淡入淡出。repeat_from_seconds=3；换曲后偏移超出曲长则报错。固定低音量、无播报闪避不变。
