## 强制验证与部署

修改投稿器后，在`D:/Basement/Codex_Video/codex-upload-video`执行：

```text
python -B validate.py --node NODE_EXE --browser CHROME_EXE --puppeteer PUPPETEER_MODULE
```

验证必须实际启动未登录的隔离Chrome。所有页面请求被拦截，本地表单仅模拟回执，不向平台投稿。不允许把未设置浏览器而跳过的测试当作通过。Python契约检查、原生封面专项检查及包含声明、标签、活动、合集、晚到字段变化和提交守卫的整表单联测全部成功后，生成`.validation/latest.json`与日志。

记录绑定投稿器全部运行模块、公开技能文件、全部测试与夹具、验证程序以及检查日志哈希。任何相关文件变化均使旧记录失效。随后在生产目录执行：

```text
python -B sync_upload_skill.py --apply --installed
python -B sync_upload_skill.py --check --installed
```

缺记录、失败、跳过、测试证据损坏或源码变化时，部署在复制文件前拒绝。部署期间桥接器拒绝新开浏览器；复制后核对所有文件和完整运行模块指纹，异常回滚并保留备份；最后更新生产配置与验证证据。每期沿用`--check --installed`和既有doctor，无需每期重跑离线测试。

恢复不设固定次数上限。每次仍需成功平台回查及submit_started=false证据；封面/定位错误会记录代码及公开上传输入签名。同样错误且输入、实现均未改变时，返回REPAIR_REQUIRED，阻止小时任务无效重复。修复、验证、部署后可继续恢复；不清零历史次数，不修改已发布稿。

## 验证边界与本轮记录

本轮新增检查验证的是实际Chrome中的脱敏原生结构与交互契约，包含正向及必须拒绝的情形。没有用已发布视频试改、试传，没有新的平台真实提交；不能把离线回归说成平台新链路已实发。平台未来改版时，未知结构应在提交前停止并给出定位证据，再更新夹具、验证和部署。
