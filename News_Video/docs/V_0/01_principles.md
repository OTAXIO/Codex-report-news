# 01｜项目原理与系统架构

## 这个项目解决什么问题

V_0 把新闻来源整理、中文播报、本地配音、字幕画面、封面、B 站投稿串成一条可追踪的流水线。目标是北京时间 06:00、12:00、18:00 分别产出早间、午间、晚间新闻，同时为 tibo 额度重置和公司新模型正式发布生成独立临时新闻。

它不是一个安装后就永远自行判断新闻的单体程序。Python 脚本承担确定性操作；当前 Codex 会话及应用自动任务承担选题、读原文、语义核验和文稿。项目没有另配一个每小时自动调用的新闻大模型 API；换成 DSH 后，执行模型、工具权限和计费需要在 DSH 中重新准备。

## 三层分工

| 层 | 做什么 | 主要实现 |
| --- | --- | --- |
| 编排与编辑 | 启动任务、核实消息、判断是否值得播报、写中文稿和封面标题 | Codex 自动任务、help-me-speech、项目规则 |
| 本地生产 | 抓取、去重、队列、语音、时间对齐、HTML 画面、字幕、渲染、归档 | News_Video、Voice_Generate、SQLite、HyperFrames、FFmpeg |
| 外部连接 | 读取 X、管理浏览器登录、操作 B 站投稿和回查 | Agent Reach、codex-upload、受管 Chrome |

一次正常制作的依赖关系是：

```text
RSS / 官网 / X 原帖
        ↓
本地正文缓存 + SQLite 候选库
        ↓
去重 + 编辑核验 + 重要回顾
        ↓
episode.json + script.txt + publication.json
        ↓
本地 Qwen3-TTS → 本地文本对齐 → 逐句时间
        ↓
单行字幕 + 分段导航 + HTML 新闻页 + 双比例封面
        ↓
检查与真实截图 → MP4 解码及导航验证
        ↓
release 成品包 → 自动投稿 → 回执 → 公开发布核验
        ↓
使用日志 / 事件状态 / 本期残留清理
```

## 数据采集为什么不必每次调用 AI

RSS、页面解析、作者校验、日期过滤、哈希和数据库插入都可以用固定规则完成。小时采集不调用模型 API，不每小时做全站 X 搜索或新闻重排。AI 只在确实需要理解时参与，例如判断一句 reset 是正式通知、请求还是玩笑，以及把几条官方公告整理成适合中文播报的内容。

AI 官方来源在每期制作前刷新。当前有原生 RSS/Atom，也有从官方网页抽取带日期条目的本地转换，后者不能叫“官方原生 RSS”。X 通过已安装的 Agent Reach 只读渠道读取，来源失败时记录缺口，不凭标题补造正文。

## 两条临时新闻通道

| 触发 | 小时脚本做什么 | 编辑必须确认什么 |
| --- | --- | --- |
| tibo reset | 检测新线索并进入 needs_review | 是否确实为额度重置，原时间、时态、范围及回复/引用上下文 |
| 官方新模型 | 检测发布关键词和模型线索并入队 | 是否为新模型正式发布，准确名称、开放状态、上下文及是否同一旧版本 |

关键词命中只代表需要查看，不等于准许发稿。确认后沿用用户已经授予的自动制片及最终提交授权，无需逐期再次询问；平台登录、验证码、限流等真实阻塞仍需处理。

新模型事件按公司和完整型号版本去重；同一版本的补帖不会自动再发一条临时新闻。两个队列初次运行先建立缓存基线，避免把旧公告集中当成新消息。紧急消息当前采用 6 小时新鲜度窗口，具体配置及核验规则见对应 alert 模块。

## 为什么去重后主片还能回顾

普通候选会排除已完成视频中的新闻。`important_events.py` 另从有公开发布核验记录的临时成品中提取近 24 小时重要事件，提供给主片回顾。

回顾必须保留原 item_id、原发布时间和已发视频链接，并标为 `editorial_role=recap`。因此同一消息可以在临时新闻中先播，再在早午晚主片中回顾，但不能重复包装成另一条“最新临时新闻”。

## 语音和字幕如何保持一致

1. 同一条新闻连续合成，减少逐句重新采样造成的语气变化。
2. `speech_text.py` 仅调整 TTS 文本，例如“调用”用同音字引导 diào，版本号与 Terra 等后缀连成完整语音单元。
3. 本地 FunASR 结合波形静音区间恢复句界。缺少可靠句界时报错，不盲切发音。
4. 模型名内部较长纯静音、句间停顿、新闻间停顿分别处理。
5. 显示稿恢复正式拼写，字幕依照处理后音频的样本数计算时间；不会把“掉用”等读音引导字放进字幕。

当前是 Qwen3-TTS 0.6B Base 参考音频克隆，尚未完成 Qwen 微调训练。语音自然度、轻声和具体读音不能仅凭程序运行成功宣称完美。

## 视频如何生成

`build_film.py` 将事实页、logo、来源时间、单行字幕和底部导航组成可编辑 HTML。HyperFrames 按时间取画面，FFmpeg 编码为视频并混入配音。当前可靠导出采用 snapshots 加 FFmpeg 的路径，包含每个字幕切点，并让最终 MP4 的全片进度条持续变化。

固定时间求值使画面可重复检查；渲染后还会实际解码并抽查每条导航高亮。仅 HTML 存在或检查通过，都不等于成片和投稿已成功。
